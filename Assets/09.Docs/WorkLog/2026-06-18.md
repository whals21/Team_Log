## 1. 런타임 버그 수정 (3건)

### 1-1. ConfigPanel 레이아웃 잘림 — `BattleTestSceneBuilder.cs`

**문제**: 패널 앵커가 0.1-0.9(80%)라 유물 행 6번 슬롯이 화면 밖으로 잘림.

**해결**: 패널 앵커를 0.02-0.98(96%)로 확장. 라벨 폭 100→80, 드롭다운 폭 170→150, 슬롯 높이 22→30 조정.

### 1-2. _pendingTestBattle 플래그 생명주기 버그 (CRITICAL) — `BattleTestSceneSetup.cs`

**문제**: 자기 리로드 사이클에서 `_pendingTestBattle`이 `OnDestroy()`에서 클리어됨. Unity 실행 순서상 옛 인스턴스의 `OnDestroy()`가 새 인스턴스의 `Start()`보다 먼저 실행되어 플래그가 premature clear됨. 결과: "전투 시작" 클릭 → 씬 리로드 → 새 `Start()`가 false 분기(설정 모드) 진입 → 즉시 설정 패널 복귀.

**해결**: 플래그를 `Start()`에서 consume 패턴으로 변경. `OnDestroy()`는 no-op.

```csharp
private void Start()
{
    if (_pendingTestBattle)
    {
        _pendingTestBattle = false; // ★ Start에서 소비
        // ... battle mode
    }
    else { /* config mode */ }
}

private void OnDestroy()
{
    // ★ 플래그 클리어 금지 — Start()에서 consume
}
```

### 1-3. BattleUICanvas 렌더링 겹침 — `BattleTestSceneBuilder.cs`

**문제**: BattleScene 복사 시 BattleUICanvas가 활성 상태로 남아 ConfigCanvas(sortingOrder=200)와 겹침. BattleUICanvas가 ScreenSpaceCamera 모드라 카메라에 렌더링됨.

**해결**: 빌더에서 `battleSetupGO.GetComponentInParent<Canvas>()`로 찾아 `Canvas.enabled = false`. GO는 활성 상태로 유지하여 Awake/Start 정상 호출. 런타임에 `BattleTestSceneSetup.Start()`에서 전투 모드 진입 시 `enabled = true`로 재활성화.

## 2. 드롭다운 팝업 빈칸 — 근본 원인 분석 및 수정

### 증상

드롭다운 클릭 시 팝업 항목 리스트가 빈 칸으로 표시됨. 이전 수정(Item 구조 정리, Template 높이, 패널 레이아웃) 후에도 지속됨.

### 근본 원인

**TMP_Dropdown.cs 소스 코드 직접 분석 (L958-965)**:

TMP_Dropdown.Show()가 팝업 항목의 위치와 크기를 **수동으로 설정**함:
```csharp
for (int i = 0; i < m_Items.Count; i++)
{
    RectTransform itemRect = m_Items[i].rectTransform;
    itemRect.anchorMin = new Vector2(itemRect.anchorMin.x, 0);
    itemRect.anchorMax = new Vector2(itemRect.anchorMax.x, 0);
    itemRect.anchoredPosition = new Vector2(...);
    itemRect.sizeDelta = new Vector2(itemRect.sizeDelta.x, itemSize.y);
}
```

TMP_Dropdown은 Content에 VerticalLayoutGroup이 있을 것을 가정하지 **않음**. TMP_DefaultControls.CreateDropdown() 표준 구조도 Content에 어떤 레이아웃 컴포넌트도 두지 않음.

**간섭 메커니즘**:
1. TMP_Dropdown.Show() → 항목 생성 + 수동 위치 지정
2. VerticalLayoutGroup이 다음 프레임에 항목 재배치
3. ContentSizeFitter가 Content 높이 재계산
4. 항목이 0px로 collapse → 빈 팝업

### 수정 내용 — `BattleTestSceneBuilder.cs`

| 항목 | 수정 전 | 수정 후 | 이유 |
|------|--------|---------|------|
| Content VerticalLayoutGroup | 있음 | **제거** | TMP_Dropdown 수동 위치 지정과 충돌 |
| Content ContentSizeFitter | 있음 | **제거** | TMP_Dropdown이 직접 Content 크기 설정 |
| Item LayoutElement | 있음 | **제거** | TMP_Dropdown이 rect.size를 직접 읽음 |
| ScrollRect visibility | AutoHide | AutoHideAndExpandViewport | TMP 표준 |
| ScrollRect spacing | 0 | -3 | TMP_DefaultControls 표준값 |
| Viewport Image.color | Color.clear | Color.white | Mask용 alpha=1 보장 |
| Viewport pivot | (0.5, 1) | (0, 1) | TMP_DefaultControls 표준 |

### Mask.Reset() 함정 발견

`AddComponent<Mask>()` 직후에 Editor 전용 `Mask.Reset()`이 실행되어 `Image.color`를 (0,0,0,0)으로, `RectTransform.pivot`을 (0.5,0.5)로 리셋하는 현상 발견.

**해결**: Mask 추가 **후에** color와 pivot을 설정:
```csharp
var viewportImg = viewportRect.gameObject.AddComponent<Image>();
var viewportMask = viewportRect.gameObject.AddComponent<Mask>();
viewportMask.showMaskGraphic = false;
// ★ Mask.Reset() 이후에 설정해야 리셋되지 않음
viewportImg.color = Color.white;
viewportRect.pivot = new Vector2(0, 1);
```

### 드롭다운 Item 구조 TMP 표준 일치화

TMP_DefaultControls.CreateDropdown() 표준 구조와 정확히 일치하도록 Item 구조 정리:
```
Item (Toggle only — 자체 Image 없음)
├── Item Background (Image → Toggle.targetGraphic, 어두운 배경)
├── Item Checkmark (Image → Toggle.graphic, 노란색)
└── Item Label (TextMeshProUGUI → dropdown.itemText, 흰색 텍스트)
```

DropdownItem 컴포넌트는 protected internal class라 외부에서 수동 AddComponent 불가 (CS0122). TMP_Dropdown.SetupTemplate()이 Show() 시점에 자동으로 Item에 DropdownItem을 추가하고 `dropdown.itemText`에서 m_ItemText를 가져옴. 수동 추가 불필요.
