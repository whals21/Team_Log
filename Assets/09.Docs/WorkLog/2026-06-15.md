## 작업 8: VFX 표시 문제 해결 — ScreenSpaceOverlay → ScreenSpaceCamera 전환

### 배경
작업 7에서 VFX 시스템을 구현했으나 런타임에서 스킬 이펙트가 화면에 표시되지 않음 (화면 플래시만 보임). 원인 분석 및 해결.

### 원인 분석 (코드 정적 분석 기반)

**핵심 원인: ScreenSpaceOverlay Canvas가 URP Camera Stacking 결과물을 가림**

- `BattleUICanvas.renderMode = ScreenSpaceOverlay` — 렌더 파이프라인 무시, 화면에 마지막에 직접 그려짐
- `BattleUIRoot`의 배경 Image: `m_Color: {r:0.08, g:0.08, b:0.16, a:1}` — 화면 전체 불투명
- URP Camera Stacking 결과 → 그 위에 ScreenSpaceOverlay Canvas → VFX 100% 가려짐
- 반면 BattleScreenFlash는 BattleUICanvas 자식 Image라서 정상 표시됨

**부가 문제:**
- Main Camera transform scale `(0.01)` — 비정상값 (BattleUISceneBuilder가 카메라 미설정)
- Main Camera cullingMask `4294967295` — 전부 (VFX 중복 렌더링 위험)
- Main Camera에 `UniversalAdditionalCameraData` 직렬화 없음

### 해결: Canvas를 ScreenSpaceCamera로 전환

ScreenSpaceOverlay는 URP Camera Stacking과 양립 불가능하므로 모드 전환.

#### 8-A. BattleUISceneBuilder.cs CreateCanvas 재설계

- `renderMode = RenderMode.ScreenSpaceCamera`, `worldCamera = mainCam`
- `planeDistance = 10`
- **신규 헬퍼 `EnsureMainCamera()`**: 기존 Main Camera 재사용 + 설정 정규화
  - Transform: position (0,0,-10), rotation identity, **scale (1,1,1)** (이전 0.01 교정)
  - orthographic size = Screen.height/200 (VFX Camera와 정합)
  - `cullingMask = ~(1 << 30)` — VFX 레이어 제외 (Overlay Camera 전용)
  - clearFlags SolidColor, backgroundColor BgDark
  - AudioListener 중복 방지

#### 8-B. TooltipUI 호환성 수정

- 라인 87 `renderMode != ScreenSpaceOverlay` 가드 제거 — 양쪽 모드 지원
- `ScreenPointToLocalPointInRectangle` 5곳: `null` → `_parentCanvas.worldCamera`
  - ScreenSpaceOverlay → worldCamera null (종전 동작 유지)
  - ScreenSpaceCamera → worldCamera 자동 사용

#### 8-C. VFXManager 재설계

- `_mainCamera` 필드 추가 — parentCanvas.worldCamera 우선, Camera.main 폴백
- VFX Camera가 Main Camera의 `orthographicSize`, `position`, `rotation` 상속 → Camera Stacking 정합성
- **`PanelToVFXWorld` 신규 메서드**: ScreenSpaceCamera 모드에서 `panelRT.position` (월드 좌표) 직접 사용, z=0 평면에 배치
- 기존 `ScreenToVFXWorld` 제거 — screen 픽셀/100 변환은 ScreenSpaceOverlay 전용이라 부적합

## 작업 9: 툴팁 커버리지 전면 수정

### 문제
VFX 작업 중 발견: 플레이어/적 스킬, 상태이상, 특성 중 일부에 마우스 호버해도 툴팁이 표시되지 않음.

### 감사 결과 (4개 갭 식별)

| 위치 | 문제 |
|------|------|
| CharacterPopupUI.PopulateSkills | 스킬 엔트리에 툴팁 없음 — 상세 팝업에서 스킬 정보 안 뜸 |
| CharacterPopupUI.PopulateStatusEffects | 상태이상 엔트리에 툴팁 없음 |
| EnemyDetailPanel.SetupTraitArea | TooltipTarget 대신 EventTrigger + BattleUIManager.ShowTraitInfo 사용 (일관성 위배) |
| ActionSlotUI.Clear | 이전 스킬 툴팁 잔류 — 빈 슬롯에도 툴팁이 뜨는 버그 |

### 해결

**1. CharacterPopupUI 스킬/상태이상 툴팁 추가**
- `AttachSkillTooltip` 헬퍼 신설 — 엔트리에 TooltipTarget 부착, 이름/요약/설명 설정
- PopulateSkills: 적 "다음 행동" 인텐트 엔트리 + 각 스킬 엔트리에 툴팁
- PopulateStatusEffects: 각 상태이상 엔트리에 GetEffectLabel/GetEffectDescription 툴팁
- BuildSkillSummary는 BattleDisplayUtil.BuildSkillDescription에 위임

**2. EnemyDetailPanel 특성 TooltipTarget 통합**
- EventTrigger + ShowTraitInfo/HideTraitInfo 호출 제거
- TooltipTarget.SetContent($"[{traitLabel}]", traitDesc) 직접 부착 — 다른 UI와 동일 패턴
- 부작용: BattleUIManager.ShowTraitInfo/HideTraitInfo가 사용처 없음 (public API라 잔존, 향후 GC 대상)

**3. ActionSlotUI.Clear 툴팁 비우기**
- GetComponent<TooltipTarget>().SetContent("", "", "") 추가
- 이전 스킬 툴팁이 빈 슬롯에 뜨는 버그 수정

### 검증
- 리컴파일: 0에러, 27경고 (기존 24 + 3 — 모두 기존 코드의 미사용 필드 관련, 신규 코드 아님)
- Unity 콘솔: 런타임 에러/경고 0건
- 단위 테스트: 61/61 통과
