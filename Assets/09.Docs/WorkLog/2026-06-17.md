### 2. 임계 버그 수정 #1 — OnKill 트리거 키워드 누락

**증상**: VampireFang(OnKillHeal +5), SlayerSigil(StackingPowerOnKill) 유물이 작동하지 않음. (테스트 3개 실패)

**근본 원인**:
- `RelicHandler.QueryKeywordSum`이 `kw.Trigger == KeywordTrigger.Passive`로 필터링
- `SkillExecutor.GetAllKeywordSum`도 동일하게 Passive만 합산
- OnKill 트리거 키워드는 어그리게이션에서 제외됨

**해결** (`Assets/02.Scripts/Reward/RelicHandler.cs`):
- 신규 헬퍼 `GetOnKillHealValue()`: 트리거 무관 `OnKillHeal` 합산
- 신규 헬퍼 `GetStackingPowerValue()`: 트리거 무관 `StackingPowerOnKill` 합산
- `GetBonusOutgoingDamage()`가 `GetStackingPowerValue() * _killStackCount` 사용

**해결** (`Assets/02.Scripts/Combat/Turn/SkillExecutor.cs`):
- `ExecuteAttack`의 OnKillHeal 처리 블록에서 `relicHandler.GetOnKillHealValue()` 추가 조회

### 3. 임계 버그 수정 #2 — Full Run 시뮬레이터 유물 무효

**증상**: BalanceSimulator의 Full Run 100회 결과 클리어율 0.0% (2026-06-16). 유물이 아예 작동하지 않는 것이 의심됨.

**근본 원인** (`Assets/02.Scripts/Editor/BalanceSimulator.Run.cs`):
- `RunSingleRun`이 GameRunState.Create + StartRun은 호출하지만
- `RelicHandler.SetPlayerParty` / `SubscribeEvents`를 **한 번도 호출하지 않음**
- 게다가 매 전투 후 `ClearCombatEventBus()`가 모든 구독을 제거하므로, 설령 초기 구독되더라도 다음 전투에서 유물이 동작하지 않음

**해결** (`BalanceSimulator.Run.cs:RunSingleRunWithState`):
```csharp
// 매 전투마다 RelicHandler 재구독 — ClearCombatEventBus가 모든 구독을 제거하므로
// 유물 트리거(OnTurnStart/OnKill/OnShieldGained 등)가 정상 작동하려면
// 전투 시작 전 SetPlayerParty + SubscribeEvents 호출 필수.
var runState = GameRunState.Instance;
if (runState != null)
{
    runState.RelicHandler.UnsubscribeEvents();
    ClearCombatEventBus();
    runState.RelicHandler.SetPlayerParty(party);
    runState.RelicHandler.SubscribeEvents();
}
// ... [전투 실행] ...
if (runState != null)
    runState.RelicHandler.UnsubscribeEvents();
ClearCombatEventBus();
```
검증된 패턴(`BalanceSimulator.Synergy.cs`)과 동일한 구독 생명주기 적용.

# Phase 7G: 인터랙티브 전투 테스트 씬 (BattleTestScene)

## 개요

사용자가 파티/유물/적/층을 직접 세팅해서 **실제 런타임 전투 씬(BattleSceneSetup)** 으로 전투를 진행할 수 있는 인터랙티브 디버그 씬 추가.

기존 `BalanceSimulator`(에디터 전용 헤드리스 시뮬레이터, UI 없음)와 달리 실제 런타임 전투 로직·UI·VFX·사운드를 모두 타기 때문에 **가장 강력한 런타임 검증 도구**. 유물 시너지, 적 특성, 층별 스케일링, 순차 적 턴, 데미지 VFX 등 모든 시스템을 눈으로 확인 가능.

## 설계 결정

- **단일 씬 구성**: 설정 패널(ConfigCanvas)과 전투 UI(BattleUICanvas)가 같은 씬에 공존. 씬 리로드로 사이클 구현.
- **자기 리로드 패턴**: `SceneManager.LoadScene("BattleTestScene")` 자기 자신을 다시 로드하여 설정 → 전투 → 설정 사이클. 모든 MonoBehaviour를 깨끗하게 재생성 (재초기화 버그 방지).
- **씬 복제 전략**: BattleScene.unity를 통째로 복사하여 BattleTestScene.unity로 생성. BattleUISceneBuilder가 만든 모든 인스펙터 참조(BattleUIManager, BattleEndOverlay, ActionSlotUI 등)를 그대로 보존 → 수동 재연결 누락 제로.
- **하위 호환성 보존**: BattleSceneSetup에 `static string _returnSceneName = "MapScene"` 추가. `SetReturnScene()` API로 다른 씬으로 복귀 가능. 아무도 호출 안 하면 기존 MapScene 복귀 동작 100% 보존.

## 아키텍처 노트

- **RelicHandler 생명주기** (`BattleTestSceneSetup.OnStartBattleClicked`): `GameRunState.Destroy → Create → SetDataPools → SetPlayerParty → SubscribeEvents → AcquireRelic` 순서. `SubscribeEvents` 누락 시 유물이 작동하지 않음 (Phase 7F에서 검증된 동일 패턴).
- **자기 리로드 안전성**: `FadeToScene` 호출 시점에 static `_pendingTestBattle = true`가 이미 설정되어 있어, 씬 전환 중 BattleTestSceneSetup이 파괴되어도 다음 씬의 새 BattleTestSceneSetup이 올바른 분기 진입.
- **BattleSceneSetup 비활성 전략**: 씬에서 BattleSceneSetup GO를 비활성 상태로 저장. BattleTestSceneSetup.Start()에서만 `_pendingTestBattle == true`일 때 SetActive(true) → BattleSceneSetup.Awake → Start 자동 호출. 스크립트 실행 순서 보장 문제 해결.
