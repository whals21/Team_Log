## 세션 A — Phase BK (BehaviorKeyword 시스템 도입, 완료)

### 배경
Team_Log는 AugmentType(18종) enum으로 "행동 변경"을, KeywordType(25종)으로 "수치 효과"를 표현하는 이원 구조를 사용 중이었다. 문제점:
1. **% 수치 난무** — Spread 70%, Pierce 50%, HeavyHit 1.5배 등 직관적이지 않음
2. **행동 키워드가 증강 전용** — 스킬 본체가 "바운스", "연쇄" 같은 행동을 가질 수 없어 Phase CC 캐릭터 컨셉(Ashe 도트 폭딜, Duran 버스트 탱커)을 데이터로 표현 불가
3. **어휘 확장 부재** — Bounce, MultiHit, Execution 같은 로그라이크 표준 어휘 부재

### 목표
AugmentType 18종을 삭제하고 **BehaviorKeyword 24종**으로 통합. 스킬 본체/증강/특성이 같은 어휘 사용. 수치는 절반/2배/3배/+N/N턴/N스택/N명/N회 형식만 허용 (% / 1.5배 금지).

### 사용자 결정 사항
- 범위/타겟팅 키워드(Spread/Bounce/Chain/MultiHit/Explosion/AOEAuto)는 **"위력 그대로"** (절반 감소 폐지)
- Execution: `rank = 절대 HP 임계값` (Execution 10 = HP 10 이하 적 즉사, 보스 제외, 런당 제한 없음)
- Bounce: 같은 적 중복 타격 허용
- Chain: 무작위 대상 선정
- Drain → Lifesteal 이름 변경 + .asset 파일명도 `Aug_Lifesteal.asset`로 변경 (GUID 재발급 감수)

### 디버깅 이슈 (4개 테스트 실패 → 161/161 통과)

1. **SkillData.cs 컴파일 에러 (CS0246)** — 원인: SkillData.cs는 `namespace TeamLog.Characters`에 있고, 원래 `using UnityEngine;`만 있었음. BehaviorTag는 `TeamLog.Skill`, IReadOnlyList는 `System.Collections.Generic`. 해결: using 2개 추가.
2. **Pierce가 쉴드에 흡수됨 (0 데미지)** — 원인: Pierce 분기에서 `TakeDamage` 호출. TakeDamage는 무조건 쉴드부터 흡수. 해결: HealthComponent.TakeDirectDamage 신설 (쉴드 우회).
3. **Lifesteal 회복량 절반 (기대 10, 실제 5)** — 원인: `power / 2`는 위력만 절반. 계획서는 "준 데미지 절반 회복". 해결: lastActualDamage 필드로 실제 입힌 데미지 추적 → Lifesteal 회복 = `lastActualDamage / 2`.
4. **AddAugment 중복 체크가 스킬 본체와 충돌** — 원인: GetBehaviorRank_SumsAcrossSkillAndAugments 테스트에서 스킬 본체 Bounce 1 + 증강 Bounce 2 = rank 3 검증. 그런데 BehaviorsMatchAny가 스킬 본체 Behavior까지 체크해서 AddAugment가 false 반환. 해결: AddAugment/IsAugmentCompatible/HasOverlappingBehavior 모두 "이미 부착된 증강과의 충돌만" 체크하도록 좁힘.
5. **Execution_DoesNotAffectBoss 보스 사망** — 원인: 보스 HP 5, 일반 공격 power 1 + ATK 5 = 6 데미지 → Execution 분기 도달 전 사망. 해결: 보스 HP 9로 조정 (TakeDamage 91).

### 학습된 교훈
- **ScriptableObject 신규 SerializeField 추가 시 using 점검**: 기존 파일에 using이 제한적이었으면 새 타입 참조를 위해 using 추가 필요. 특히 `namespace`가 다를 때.
- **행동 키워드 rank 합산 vs 중복 방지**: 스킬 본체와 증강의 rank 합산을 허용하려면 "충돌 체크"는 "증강 vs 증강"으로 한정해야 함. 스킬 본체는 데이터(불변)이고 증강은 부착/제거되는 동적 상태.

## 세션 B — Phase CC-0 (부활 시스템 기반, 완료)

### 배경
Phase CC의 선행 조건. 전투 종료 시 사망한 파티원을 50% HP로 부활 + MaxHP 영구 0.9배 누적. 파티 전멸만 런 종료. 이 정책이 있어야 Phase CC의 어센션 × 사망 누적 시뮬레이션과 캐릭터 컨셉 설계가 진행 가능.

### 정책 (CharacterConceptReview.md 부록 A에서 확정)
- **전투 승리 시**: 살아남은 자 HP 100% 회복, 사망자 50% HP 부활 + MaxHP 영구 0.9배 누적
- **파티 전멸 시**: 런 종료 (RunEndOverlay 패배 화면)
- **부활 누적 효과**: 120HP 캐릭터가 6회 사망/부활 시 120×0.9^6 = 64HP. 어센션과 중첩 시 가혹 → CC-1에서 완화 정책 검토

### 구현 상세

#### HealthComponent 확장
- `Revive(float hpPercentage)` — 사망 상태 해제, MaxHP의 percentage만큼 HP 복원. OnRevived 이벤트 발생.
- `ApplyMaxHpModifier(float multiplier)` — MaxHP 영구 조정 (기본 곱셈).
- `OnRevived` 이벤트 — 유물/특성 훅 확장점.

#### GameRunState.ProcessBattleEnd(bool victory)
- victory=true: 파티 순회 — 생존자 Heal to full, 사망자 ApplyMaxHpModifier(0.9f) 후 Revive(0.5f). IsRunEnded=false 반환.
- victory=false (전멸): IsRunEnded=true 반환.
- CombatEventBus.OnPartyMemberRevived 이벤트로 부활 알림.

#### CombatEventBus.OnPartyMemberRevived
- 14번째 이벤트. 부활한 Character를 인자로 전달.

#### BattleSceneSetup 연결
- OnBattleEnded(victory) → GameRunState.ProcessBattleEnd 호출 → IsRunEnded=true면 RunEndOverlay 패배, 아니면 MapScene 복귀.

#### 단위 테스트
- ReviveTests 신설: 부활 기본, MaxHP 0.9배 누적, HP 100% 회복, 다중 부활, 전멸 런 종료, OnRevived 이벤트.

## 세션 D — 스킬 컨셉 백로그 (사용자 제안 4종)

사용자가 구상한 스킬 메카닉 4가지를 백로그로 정리. 각 컨셉은 **"자율성 제한을 통한 보상"** 구조. Phase CC-1/CC-1B에서 적합한 캐릭터에 배정 예정.

| # | 컨셉 | 총 데미지 | 핵심 제약 | 구현 메카닉 |
|---|------|---------|---------|-----------|
| 1 | **분배 (Distribute)** | 12 | 무작위 분배, 타겟 지정 불가 | 새 BehaviorTag `Distribute` |
| 2 | **최대체력 타겟 (TargetHighestHP)** | 10 | 가장 튼튼한 적 자동 선택 | 새 BehaviorTag `TargetHighestHP` |
| 3 | **자유 다단 (MultiStrike)** | 6 (3×2) | 매 타격마다 타겟 자유 지정 | 새 BehaviorTag `MultiStrike` + 순차 타겟팅 UI |
| 4 | **풀피 타겟 (TargetFullHP)** | 10 | 풀피 적 존재 시만 사용 | 새 BehaviorTag `TargetFullHP` + CanUse 검사 |

### 공통 패턴
단일기 위력 8 기준으로 +25~50% 또는 -25%. "원하는 적을 골라서 때릴 수 없다"는 제약이 리스크/리턴의 핵심.
