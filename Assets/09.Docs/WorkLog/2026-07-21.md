### 작동 흐름
```
전투 시작 → InitializeBattle() → InitializeBossPhaseManager()
   ↓ 보스 감지 (IsBoss true인 _enemies[0])
   ↓ CombatEventBus.OnDamageReceived 구독
   ↓
매 데미지 → OnBossDamaged(target, amount)
   ↓ target == 보스인 경우만 CheckPhaseTransitions()
   ↓
HP 75% 도달 → HandleSummonPhase()
   ↓ _greyForestSummonPool의 적들 스폰 (Wisp + Sporecaller)
   ↓ _enemies.Add + _enemyControllers.Add
   ↓
HP 50% 도달 → HandleSplitPhase()
   ↓ 분신들 먼저 스폰 (전투 종료 방지)
   ↓ 보스 강제 사망 (TakeDamage 99999)
   ↓ 분신들이 _enemies에 있으므로 전투 계속
```

## 3차 세션: 전투 연출 시스템 후속 디버깅 (Play 모드 검증 사이클)

### 배경
2차 세션에서 Tier S+A+B 구현 완료 후 사용자 Play 모드 검증 피드백 반영. 총 6건의 버그/이슈를 순차적으로 수정.

### 이슈 1: TextMeshProUGUI vs TMP_Text 컴파일 에러 (code-reviewer P0 누락)

**현상**: 컴파일 에러 2건 (TurnBannerView.cs, SkillNamePopup.cs)
**원인**: `UIKoreanFont.EnsureFont(TextMeshProUGUI tmp)` 헬퍼가 **TextMeshProUGUI** 타입을 요구하는데, 제가 `_currentText`를 부모 타입인 **TMP_Text**로 선언. C#은 부모→자식 암시적 캐스팅 미지원.
**수정**: 두 파일의 `_currentText` 필드 타입을 `TextMeshProUGUI`로 변경.
**인사이트**: code-reviewer는 런타임 위주 검증이라 컴파일 타임 타입 mismatch를 놓침. 헬퍼 함수 시그니처 직접 검증 단계 필요.

### 이슈 2: TurnBannerView outlineWidth null reference (End Turn 시)

**현상**: End Turn 버튼 클릭 시 ArgumentNullException at `TMPro.TMP_Text.CreateMaterialInstance`
**원인**: 제가 작성한 코드:
```csharp
_currentText.fontSharedMaterial = null;  // 강제 null
_currentText.outlineWidth = 0.2f;         // null 매터리얼로 인스턴스 생성 시도 → 에러
```
`outlineWidth` setter가 내부적으로 fontSharedMaterial을 기반으로 새 Material을 생성하는데, 직전에 null로 설정해서 `new Material(null)` 호출됨.
**수정**:
- `fontSharedMaterial = null` 제거 (치명적 실수)
- outlineWidth/outlineColor 설정 전에 `fontSharedMaterial != null` 체크 추가
- SkillNamePopup에도 동일한 null 체크 추가

### 이슈 3: 슬롯 순차 등장 첫 턴 미작동

**현상**: 2번째 턴부터는 순차 등장 연출이 작동하지만 첫 턴에는 안 됨
**원인 2가지**:
1. `InitializeDirectionController()`가 `_turnManager.StartBattle()` 이후에 호출 → 첫 드로우(StartBattle 안에서 발생) 시점에 DirectionController가 null
2. `_lastDrawHadSlots`이 true로 고정되어 isNewDraw가 false → 매 턴 entrance 미트리거

**수정 (1차)**:
- InitializeDirectionController를 StartBattle 이전으로 이동
- ActionBarUI가 TurnManager.OnTurnStarted 구독하여 매 턴 시작 시 _lastDrawHadSlots=false 리셋

**수정 (2차 — 더 근본적)**: isNewDraw 판단 로직 자체를 제거. PlayerActionController.OnDrawComplete에서 명시적으로 `_actionBar.NotifyNewDraw()` 호출. 이제 매 드로우마다 확실하게 entrance 트리거.

### 이슈 4: 파티원 사망 시 슬롯 크기 확장

**현상**: 파티원 1명 사망 시 슬롯이 4개 → 3개로 줄면서 남은 슬롯들이 넓은 공간을 분배하여 크기가 커짐
**원인**:
- `SkillDrawSystem.ExecuteDraw()`가 생존 캐릭터만 슬롯에 담음
- `ActionBarUI.UpdateActionSlots`가 남은 슬롯을 `SetActive(false)` 처리
- LayoutGroup이 비활성 자식을 배치에서 제외 → 나머지 슬롯들이 공간 분배

**수정**:
- `ActionSlotUI.SetEmpty()` 신규 메서드 — Clear() + activeSelf=true 유지 (자리 차지)
- `ActionSlotUI.Clear()`에 `_button.interactable = false` 추가 (빈 슬롯 클릭 차단)
- `ActionSlotUI.SetSkill()`에 `_button.interactable = true` 추가 (활성 슬롯 클릭 가능)
- ActionBarUI.UpdateActionSlots에서 slot.Skill==null이면 SetEmpty 분기

### 이슈 5: 슬롯이 원래 위치보다 위로 나와 캐릭터 UI 가림

**현상**: entrance 연출 후 슬롯이 원래 자리로 안 돌아가고 위로 올라가서 캐릭터 패널을 가림
**원인**: `SlotEntranceAnimator.PlaySingleEntrance`에서 `rt.anchoredPosition`에 Y offset(Vector2.down * 30)을 줬는데, 이게 LayoutGroup의 자동 배치와 충돌. entrance 종료 후 원래 자리로 복귀해도 LayoutGroup이 재배치하면서 다시 밀어냄.
**수정**: anchoredPosition Y offset 조작을 완전히 제거. **scale + alpha만**으로 entrance 연출. LayoutGroup과 충돌하지 않음.

### 이슈 6: 사망한 캐릭터 슬롯 순서 틀어짐

**현상**: 중간 캐릭터가 사망하면 슬롯들이 앞으로 당겨져서 캐릭터 순서와 슬롯 순서 불일치. "사망한 캐릭터 슬롯이 가장 오른쪽으로 나옴"
**원인**: `SkillDrawSystem.ExecuteDraw()`가 죽은 캐릭터를 건너뛰어서 슬롯 순서가 당겨짐.

예시 — 캐릭터 [Duran, Ashe, Lumi, Sibyl]에서 Ashe 사망 시:
```
캐릭터 UI:  [Duran] [Ashe(빈)] [Lumi] [Sibyl]
기존 슬롯:  [Duran] [Lumi]      [Sibyl] [빈]  ← 순서 틀어짐
```

**수정**: `ExecuteDraw()`에서 죽은 캐릭터도 빈 슬롯(instance=null)로 포함:
```csharp
else
{
    // 죽은 캐릭터 — 자리 유지용 빈 슬롯
    var slot = new DrawnSkillSlot(character, null, _drawnSlots.Count);
    _drawnSlots.Add(slot);
}
```
이제 슬롯 순서 = 캐릭터 순서 항상 일치.
