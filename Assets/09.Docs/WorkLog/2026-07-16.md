## 작업 3 — TargetBox 위치/길이 문제 해결

### 문제
- 적 패널의 TargetBox가 "적 패널 중간"에 나오고, 너비가 "적 패널보다 더 김"

### 원인 (Prefab 파일에서 직접 확인)
- TargetBox의 RectTransform: `AnchorMin=(0.5,0.5)`, `SizeDelta=(0, 22)`
- 부모 panel의 VerticalLayoutGroup이 `m_ChildControlWidth: 1` — 자식 transform이 잠김
- 인스펙터 수정 불가 원인: VLG의 Child Control Width 활성화

### 해결 (IntentSlot 패턴 차용)
- `BattleUISceneBuilder.UI.Sidebar.cs`의 TargetBox 코드를 ignoreLayout=true + 명시적 앵커로 변경:
  - `anchorMin/Max=(0.5, 1)` 상단 중앙
  - `pivot=(0.5, 1)` 위쪽 끝
  - `anchoredPosition=(0, -2)` panel 내부 상단에서 2px 아래
  - `sizeDelta=(180, 22)` panel.preferredWidth=180과 일치
  - LayoutElement.ignoreLayout = true

### 사용자 수동 작업 (Prefab Mode)
- `Assets/03.Data/Prefabs/EnemyDetailPanel.prefab` 더블클릭 → Prefab Mode
- TargetBox에 LayoutElement 추가 + Ignore Layout 체크
- Anchor Top/Center, Pos(0, -2), Width 180, Height 22 적용
- 인스펙터 잠금 해제 확인 후 수정

**수정 파일**:
- `BattleUISceneBuilder.UI.Sidebar.cs` — CreateEnemyPanel TargetBox 코드
- `EnemyDetailPanel.prefab` — 사용자 수동 조정 (LayoutElement 추가)

2. **피해 시 리셋 / 무피해 시 적축** (2종): TakeDamage → 0 리셋, 무피해 N턴 → N스택

6. **Eviscerate 자원 검사** (3종): MinResourceRequired=3 차단/허용, ConsumeStacks(1) 작동

### 핵심 디버깅 — OnTurnEnd 중복 +1 함정
초기 테스트 2개 실패: `AddStacks(N); OnTurnEnd()` 패턴 사용 시, OnTurnEnd가 무피해 시 자동 `AddStacks(1)`을 더하여 N+1 스택이 됨.

**해결**: `PassTurns(c, N)` 헬퍼 추가 — OnTurnStart/End N회 호출로 런타임의 자연스러운 스택 적축 패턴 재현. 15개 테스트 모두 통과.
