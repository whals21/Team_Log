## 핵심 인사이트 (CLAUDE.md 함정 #54-58 추가)

### 54. 슬롯/툴팁 정보 분담이 명작 표준
- StS/Hearthstone/Monster Train 모두 슬롯(카드)엔 핵심 수치만, 상세는 툴팁/호버
- Team Log도 동일 패턴 적용 — 슬롯 `"23 데미지"`, 툴팁에 자연어 풀어쓰기
- **교훈**: 작은 UI 영역에 정보 압축 금지. 분담이 정답.

### 55. 자연어 vs 수식 — StS 한국어 표준
- 수식 `"위력 8+5×3=23"` → 자연어 `"적에게 8의 피해를 줍니다. 잿빛 1스택마다 추가로 5의 피해를 줍니다."`
- 행위 동사 ("줍니다", "얻습니다", "부여합니다") 필수
- 기호(≤, ×, =)를 자연어("이하", "스택마다")로 전환
- **교훈**: 초보자도 즉시 이해하려면 자연어 문장형.

### 56. Rich text 색상 강조 가독성 폭발적 향상
- TextMeshProUGUI는 기본 rich text 지원 (`<color>`, `<b>`, `<i>`)
- 골드 숫자, 주황 자원, 이탤릭 조건 색상 분리 → 시각적 계층 즉시 파악
- Balatro 벤치마크 — Team Log에도 동일 패턴 적용 가치 입증

### 57. SetAffordable(false)는 RGB도 낮춰야 일관적
- alpha만 0.3으로 줄이면 스킬 타입별 잔색 남음 (Heal=초록 잔색, Attack=빨강 잔색)
- `new Color(0.22f, 0.22f, 0.22f, 0.75f)` 식 어두운 회색으로 통일
- **교훈**: 비활성 시각은 타입 무관 일관된 톤이어야 함.

### 58. SerializeField 디버그 기본값 true의 역설 (2026-08-02 #53 연장선)
- `_useTestData = true` 기본값이 정상 런에서 CreateTestData 강제 → 스킬 툴팁 왜곡
- 툴팁 UX 검증 시 "이게 진짜 스킬 값인가?" 의심 필요
- **교훈**: UX 디버깅 시 디버그 플래그 먼저 점검.
