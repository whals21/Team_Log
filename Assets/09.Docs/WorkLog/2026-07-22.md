# 작업 일지 — 2026-07-22

## 1차 세션: CC(Stun/Freeze/Sleep) 행동 불가 구현 + 진영별 duration 감소 (A안)

### 배경
Ashwood Wisp의 쉴드 스킬(Wisp_Wobble)이 "적 턴에만 표시되고 플레이어 턴 시작 시 리셋되어 의미 없음" 문제에서 시작. 쉴드 리셋 시점을 진영별로 분리하는 A안 채택 후, 추가로 Wisp_Wobble을 자신 또는 랜덤 아군에게 부여하도록 변경.

이후 Blightbed Crawler의 매달리기(Stun 1턴) 스킬이 실제로 행동을 안 막는다는 사실 발견 → CC 행동 불가 로직 전체 구현 착수.

### Phase 1: 쉴드 시스템 재설계 (A안)

**문제**: TurnManager.StartNewTurn에서 모든 캐릭터 쉴드 리셋 → 적이 자기 턴에 건 쉴드가 다음 플레이어 턴 시작 시 리셋되어 쉴드의 의미 사라짐.

**해결**: 각 진영은 자기 턴 시작 시 자기 진영 쉴드만 리셋 (StS/Hearthstone 표준).
- `TurnManager.StartNewTurn` (플레이어 턴 시작): 플레이어 쉴드만 리셋
- `TurnManager.StartEnemyTurn` (적 턴 시작): 적 쉴드만 리셋 (신규 추가)

**영향**: 모든 적 Shield 스킬이 의미 있게 작동. Mossbulwark(이끼 방패, Self 실드 4) 진짜 탱커 역할. Wisp_Wobble도 플레이어 턴에 흡수됨.

### Phase 2: Wisp_Wobble — 자신 또는 랜덤 아군 부여

**문제**: Wisp_Wobble이 Self 타겟이라 시전자만 쉴드. 약한 서포터 느낌 안 남.

**해결**:
- `EnemyAIController`에 `_allies` 필드 + `SetAllies()` 메서드 신규
- SingleAlly 분기를 "자신 포함 랜덤 생존 아군"으로 변경
- `BattleSceneSetup` 2곳(InitializeBattle, BossPhase.SpawnEnemyFromData)에서 `controller.SetAllies(_enemies)` 호출
- `SkillTable.csv`: Wisp_Wobble target Self → SingleAlly

### Phase 3: CC 행동 불가 로직 구현 (★ 핵심)

**문제**: Stun/Freeze/Sleep이 UI 표시와 VFX/사운드는 있지만 실제 행동 불가 로직이 미구현. "장식 상태이상" 상태.

**해결 (4곳 수정)**:

1. **StatusEffectComponent.IsIncapacitated** 프로퍼티 신규:
   ```csharp
   public bool IsIncapacitated =>
       HasEffect(StatusEffectType.Stun) ||
       HasEffect(StatusEffectType.Freeze) ||
       HasEffect(StatusEffectType.Sleep);
   ```

2. **TurnManager.ExecuteSkillImmediately**: caster CC 시전 차단
   ```csharp
   if (caster.StatusEffects.IsIncapacitated) return false;
   ```

3. **TurnManager.ExecuteSingleEnemyAction**: 적 CC 행동 스킵
   ```csharp
   if (controller.Owner.StatusEffects.IsIncapacitated) return;
   ```

4. **TurnManager.ProcessTurnEnd 진영별 분리** (★ 밸런스 핵심):
   - `ProcessPlayerTurnEnd()`: 플레이어 OnTurnEnd + Resource.OnTurnEnd + ApplyStatModifiers + FireTurnEnd (StS 표준)
   - `ProcessEnemyTurnEnd()`: 적 OnTurnEnd + Charge 연쇄/소멸 + ApplyStatModifiers
   - `ConfirmActions`: StartEnemyTurn 전에 ProcessPlayerTurnEnd 호출
   - `CompleteEnemyTurn`: ProcessEnemyTurnEnd만 호출

### Phase 4: code-reviewer P0 2건 사전 차단

**P0-1: FireTurnEnd 위치 오류 (회귀)**
- 문제: FireTurnEnd가 ProcessEnemyTurnEnd에 있어서 RelicHandler/CharacterTraitHandler의 OnTurnEnd 트리거가 "적 턴 종료 시"에만 발생
- 해결: FireTurnEnd를 ProcessPlayerTurnEnd로 이동. StS 표준(플레이어 턴 종료 시) 준수

**P0-2: 시뮬레이터 비순차 모드 회귀**
- 문제: ExecuteEnemyActions가 ProcessTurnEnd(양쪽)를 또 호출하여 플레이어 상태이상/자원 효과가 2배 적용 (Ashe Ember 자해 2배 등)
- 해결: ExecuteEnemyActions에서 ProcessEnemyTurnEnd만 호출. 시뮬레이터-런타임 일관성 확보

### 새 CC 동작 흐름 (매달리기 정상 작동)
```
적 턴 N: Crawler가 플레이어에게 매달리기 → Stun 1턴 부여
적 턴 N 종료 (ProcessEnemyTurnEnd): 적 상태이상 감소. 플레이어 Stun 유지.
플레이어 턴 N+1 시작: Stun 보유 → 행동 차단
플레이어 턴 N+1 종료 (ProcessPlayerTurnEnd): Stun duration 1→0 소멸. FireTurnEnd 발생.
플레이어 턴 N+2: 정상 행동
```

### 진영별 분리 부수 효과 (밸런스 자동 보정)
- **Poison 2턴**: 기존 1턴 만에 소멸 → 정확히 2번의 자기 턴 동안 유지
- **Burn/Stun 등 모든 상태이상**: 정확한 duration 적용
- **Ashe Ember 자해 / Lumi Frost 소실**: 플레이어 턴 종료 시 1회만 (기존 2회)

### 핵심 인사이트 (CLAUDE.md/MEMORY.md 반영)
1. **CC 행동 불가 3단계**: (1) StatusEffectComponent.IsIncapacitated 헬퍼, (2) 행동 시작 시 차단 (시전자/적), (3) 진영별 duration 감소. 셋 다 있어야 StS 표준 CC 작동
2. **진영별 duration 감소가 밸런스 핵심**: 양 진영을 한 번에 감소시키면 "Poison 2턴"이 1턴 만에 소멸. 진영별로 자기 턴 종료 시 감소해야 정확한 duration. StS/Hearthstone 표준
3. **FireTurnEnd 위치 = StS 표준 준수**: 플레이어 턴 종료 시 발생해야 RelicHandler/CharacterTraitHandler OnTurnEnd 트리거가 자연스럽게 작동. 적 턴 종료로 넣으면 유물/특성이 의도보다 늦게 발동
4. **시뮬레이터-런타임 일관성**: ProcessTurnEnd를 진영별로 분리할 때 시뮬레이터 비순차 모드(ExecuteEnemyActions)도 같은 패턴 적용해야. 안 하면 시뮬레이터 밸런스가 2배 왜곡
5. **code-reviewer P0 2건 사전 차단 가치 입증**: FireTurnEnd 위치와 시뮬레이터 회귀는 런타임 Play 모드에서 발견하기 어려운 미묘한 버그. code-reviewer가 로직 분석으로 사전 식별

## 2차 세션: Taranis Charge 메커니즘 단순화 재설계

### 배경
사용자 피드백: "Taranis의 Charge 메커니즘이 너무 복잡하다. 전파와 스택형 도트 데미지 특성을 살리면서 더 간단하고 직관적으로 바꿔라."

기존 메커니즘 문제: 규칙 8개 (연쇄/자폭 분기, Charge 적끼리만 연쇄, 스택수 비례, duration/value 이원 관리, Propagate, Explosion, GivesChargeOnAbsorb). 플레이어가 이해하기 어렵고, "네트워크 딜러" 컨셉이 규칙 속에 묻힘. 또한 밸런스 문제 — 보스전(단일)에서 딜이 거의 안 들어감.

### 기획 과정
1. **4가지 개선안 제안** (충전 폭발/전염/충전지/수치 조정)
2. **사용자 선택**: "Charge 고정 3 도트 + 매 턴 -1 차감 + 자기 자신에게만 + 즉발 데미지 없음"
3. **밸런스 검증**: 서브 에이전트(전투 밸런스 분석)로 다른 캐릭터 대비 DPS 비교
4. **Branch vs Thunderstorm 밸런스 조정**: Thunderstorm Charge 3→2 (cost 1 차이에 데미지 3배는 과도)
5. **최종 디자인 확정**: 사용자가 "단점(타이밍 늦음/원콤 불가) vs 장점(지속딜+광역딜)" 밸런스 축 명확히 이해

### 최종 메커니즘 (규칙 1개)
> Charge 보유 적이 매 턴 종료 시 **고정 3 데미지**를 자기 자신에게 받음. 도트 후 Charge **-1**. Charge 스택 = 지속 턴 수.

### 스킬 4종

| 스킬 | 타입 | Charge | 타겟 | Cost | 총 도트 |
|------|------|--------|------|------|---------|
| Wire | Debuff | 3 | 단일 | 1 | 9 (3턴) |
| Branch | Debuff | 1 | 광역 | 2 | 3/적 (1턴) |
| Grounding Field | Shield | — | 아군 전체 | 2 | 쉴드 3 |
| Thunderstorm | Debuff | 2 | 광역 | 3 | 6/적 (2턴) |

### 디자인 철학
- **단점**: 즉발 데미지 없음 → 적 행동 후 도트 → 타이밍 늦음, 원콤 불가
- **장점**: 지속딜 + 광역딜 → 데미지 총량 높음
- **역할**: 안정적 지속 딜러 (매 턴 1 AP로 3/턴 확보)

### 제거된 복잡성

- Wire Propagate behavior
