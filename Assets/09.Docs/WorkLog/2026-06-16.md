## UI 툴팁 시스템 버그 수정 (Phase B)

플레이테스트에서 발견된 3가지 호버 툴팁 문제 수정.

### 문제 분석
1. **가장 왼쪽 적 스킬 툴팁 위치 이탈**: 마우스에서 멀리 날아감
2. **플레이어 스킬 툴팁 미표시**: PlayerSidebarPanel에 TooltipTarget 컴포넌트 자체가 없었음
3. **적 특성 툴팁 미표시**: TraitLabel이 정상 생성되나 hover가 안 잡힘

### 근본 원인

**1. TooltipUI.UpdatePosition() 월드 좌표 기반 클램핑**
- 기존 코드가 월드 코너(`corners[0].x < 0`) 기반으로 화면 경계 검사
- ScreenSpaceCamera 모드에서는 월드 원점 (0,0,0)이 화면 좌측하단이 아님
- 카메라 z=-10, 평면거리 10 → 월드 원점이 화면 중앙 부근
- 마우스가 화면 좌측일 때 `corners[0].x < 0`이 자주 발동 → 툴팁이 부모 RectTransform 로컬 영역으로 튕겨나감

**2. PlayerSidebarPanel 구현 누락**
- EnemyDetailPanel은 IntentSlot에 TooltipTarget이 있으나, PlayerSidebarPanel엔 전혀 없었음
- 모든 자식 Graphic이 `raycastTarget = false` 처리되어 hover 이벤트 자체 불가

**3. EnemyDetailPanel.SetupTraitArea의 TraitLabel 취약점**
- `labelRect.anchorMin/Max`가 기본값 (0,0)/(1,1) → 부모 ButtonArea(sizeDelta 0,24)에서 음수 크기로 왜곡
- `Image.sprite`가 null → 일부 환경에서 Graphic이 Raycast 무시
- LayoutElement 미부착 → HorizontalLayoutGroup이 자식 크기 임의 왜곡

### 수정 내역

| 파일 | 변경 |
|------|------|
| `TooltipUI.cs` | `UpdatePosition()` 전면 재작성 — 스크린 픽셀 기반 클램핑(`WorldToScreenPoint`)으로 전환, 모든 캔버스 모드에서 정합 |
| `PlayerSidebarPanel.cs` | Awake에서 TooltipTarget 부착 + 부모 Image.raycastTarget 보장(null sprite일 때 WhiteSprite 할당), Setup/UpdateHP/UpdateStats/UpdateStatusEffects에서 `UpdateTooltipContent()` 호출로 스탯/HP/상태이상/보유 스킬 4종 표시 |
| `EnemyDetailPanel.cs` | TraitLabel anchorMin/Max=(0.5,0.5) 명시, WhiteSprite로 Image.sprite 보장, LayoutElement(preferred/min 160x32) 부착, ButtonArea 자동 생성 시 childControlWidth/Height/ForceExpand=false 명시 |
| `BattlePanelBase.cs` | `UpdateStats`, `UpdateStatusEffects` virtual 키워드 추가 (PlayerSidebarPanel override 허용) |

# 적 턴 순차 실행 (Sequential Enemy Turn)

## 문제
적 턴에 모든 적이 스킬을 단일 프레임에서 동시 실행 → VFX·플로팅 텍스트·카메라 흔들림·히트스톱이 한꺼번에 발생해 누가 무슨 스킬을 썼는지 구별 불가. 조사한 모든 턴제 게임(Slay the Spire, Into the Breach, Persona 5, Honkai: Star Rail, Darkest Dungeon)이 순차 실행 사용.

**근본 원인**: `TurnManager.ExecuteEnemyActions()`가 foreach로 모든 적의 `controller.ExecuteAction()`을 동기 호출 → 같은 프레임에 모든 데미지/VFX 이벤트 발생.

## 핵심 설계 원칙
1. **TurnManager는 순수 C# 유지** — 코루틴은 BattleSceneSetup(MonoBehaviour)에서 실행
2. **시뮬레이터 호환성** — 기본값은 동기 모드, `EnableSequentialEnemyTurn()` 호출 시에만 코루틴 모드
3. **이벤트 기반 분할** — ConfirmActions → StartEnemyTurn → `OnEnemyTurnSequenceStarted` 이벤트 → BattleSceneSetup 코루틴 → 적마다 `ExecuteSingleEnemyAction()` → 종료 후 `CompleteEnemyTurn()`
4. **Time.timeScale 자동 호환** — `WaitForSeconds`는 timeScale의 영향을 받아 1x/2x 전투 속도 자동 적용
5. **데미지 중간 사망 처리** — 매 적 행동 후 `IsBattleEndedEarly()` 체크 → 파티 전멸 시 즉시 종료

## 구현 내용

### TurnManager.cs — 분할 API
- `_sequentialEnemyTurn` 플래그 + `EnableSequentialEnemyTurn()`
- 신규 이벤트: `OnEnemyTurnSequenceStarted` (코루틴 시작 알림), `OnEnemyActing(Character)` (개별 적 행동 시작)
- `EnemyControllers` 프로퍼티 (IReadOnlyList) — 코루틴 순회용
- `ExecuteSingleEnemyAction(controller)` — 적 1명 행동 + OnEnemyActing 발행
- `CompleteEnemyTurn()` — ProcessTurnEnd + CheckBattleEnd + StartNewTurn (ExecuteEnemyActions 후반부와 동일)
- `IsBattleEndedEarly()` — 파티/적 전멸 체크
- `StartEnemyTurn()` 분기: `_sequentialEnemyTurn` true면 이벤트 발행 후 return, false면 기존 동기 `ExecuteEnemyActions()` (시뮬레이터)

### BattleSceneSetup.cs — 활성화 + 구독
- InitializeBattle에서 TurnManager 생성 후 `OnEnemyTurnSequenceStarted`/`OnEnemyActing` 구독 + `EnableSequentialEnemyTurn()` 호출

### BattleSceneSetup.Events.cs — 코루틴
- 타이밍 상수: `EnemyTurnEntryDelay=0.30s`, `EnemyHighlightDelay=0.15s`, `EnemyActionVfxDelay=0.55s` (WaitForSeconds → timeScale 자동 적용)
- `_isEnemyTurnRunning` 가드로 중복 실행 방지
- `ExecuteEnemyTurnSequence()` 코루틴: 진입 대기 → foreach 적 → ExecuteSingleEnemyAction → 의도 클리어 → VFX 대기 → 하이라이트 해제 → 전멸 체크 → CompleteEnemyTurn. try/finally로 가드 해제
- OnDestroy에서 신규 구독 해제

### BattleUIManager.cs — 하이라이트/의도 API
- `HighlightActingEnemy(enemy)` / `ClearActingEnemyHighlight(enemy)` — 패널 위임
- `ClearEnemyIntentFor(enemy)` — 행동 마친 적 의도 즉시 비움 ("이미 행동함" 시각화)
- `GetEnemyPanelFor(enemy)` — Character → EnemyDetailPanel 매핑 헬퍼

### EnemyDetailPanel.cs — 하이라이트 시각
- `Target` 프로퍼티 추가 (_character 노출)
- `HighlightActing()` — DOTween.To() 직접 사용 스케일 펀치(1.0→1.08→1.0, 0.18s) + 따뜻한 강조 배경색(1, 0.92, 0.65)
- `ClearActingHighlight()` — 트윈 Kill + 스케일 1.0 복원 + 기본 배경색 복원
- Awake에서 InitPanelBase 후 `_defaultBgColor` 캡처
